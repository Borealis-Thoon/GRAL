# POINT·PORTAL·정상상태 GPU 실행의 독립 결과 검토

두 실행 모드의 판정은 `engineering_pass_observed_fixture`다. 44개 실행의 원시 GRZ를 독립적으로 해독해 계산한 지표가 분석 결과와 일치했고, 편향·꼬리 농도·최대값·농도 지도를 검토한 범위에서 수치 판정을 뒤집을 근거는 발견되지 않았다. 정상상태 48상황에서는 CPU 시간 변동이 커 성능 재현성을 검토 항목으로 남긴다. 이 판정은 고정한 입력·빌드·시험 장치에서의 구현 비교에 한정한다. 물리적 타당성, 보편적인 과학적 동등성, 정식 동등성 검정은 확립되지 않았다.

검토는 원시 배열·실행 영수증 검산, 사전 정의한 수치 기준 확인, 진단 지표와 그림 해석, 시간·메모리 측정 범위 확인 순서로 진행했다. `qa/independent_raw_review.json`의 38,431개 점검이 모두 통과했다. 이 수에는 배열 구조·자료 존재·수치 대조가 포함된다. 분석 모듈을 가져오지 않는 별도 해독기로 두 cohort의 22개 실행씩을 확인했으며, 이번 작업에서 모델을 재실행하지 않았다. 검토 스크립트·프로토콜·분석 요약·직접 본 그림의 SHA256은 `qa/scientific_result_review.json`에 묶었다. 전체 28개 그림과 분석 전후 원자료 해시의 최종 확인은 별도 통합 QA에 속한다.

SG1 AREA, SG2 horizontal LINE, SG3 POINT, SG4 PORTAL 및 합계를 각각 평가했다. 두 모드는 합치지 않았다. 비정상상태의 24/48상황은 잔류 입자가 이어지는 연속 한 시간 간격이고, 정상상태의 24/48상황은 각각 3600초를 기준으로 계산한 정상 기상상황의 수다. 정상상태에서 다음 상황으로 잔류 입자를 넘기지 않는 계약도 검산했다. 주 비교 구간은 상황 4..24이며 전체 24상황 비교는 보조 결과로 유지했다.

모드별 과학 비교에는 여섯 seed 설정과 사전에 정한 세 개의 겹치지 않는 seed 쌍을 사용했다. R은 같은 seed의 CPU/GPU L1 차이를 쌍 안에서 평균한 뒤 CPU interseed L1으로 나눈 값이다. V는 GPU interseed L1을 CPU interseed L1으로 나눈 값이다. 모든 배출원군과 합계에서 R<1, V의 검토 범위 0.5..2를 충족했다. 분모는 모두 양수여서 비교 결과를 informative로 분류했다. 원시 배열은 유한한 비음수 값으로 구성됐고 각 실행의 네 배출원군에서 양의 출력을 확인했다.

| 주 비교 지표 | 비정상상태 | 정상상태 |
|---|---:|---:|
| R 최댓값 | 0.0007580877 | 0.0008232450 |
| NMAE 범위 | 0.0000054987..0.0000202915 | 0.0000070192..0.0000185976 |
| 정규화 편향 절댓값 최댓값 | 0.0000048561 | 0.0000022592 |
| 공간 상관계수 최솟값 | 0.999999999814 | 0.999999999846 |
| CPU/GPU 최대값 위치 일치 | 30/30 비교 | 30/30 비교 |

정규화 편향은 각 배출원군의 여섯 seed에서 양·음이 모두 나타났다. 모든 최대값의 상황·격자 위치가 일치했고, seed 0 평균 지도에서도 주요 플룸의 위치와 형태가 유지됐다. 격자별 최대 절대차는 비정상상태에서 0.1613846, 정상상태에서 0.0949669였다. 이 수치는 원자료 농도 단위이며, 최대 상대오차나 오차 허용치로 해석하지 않는다. 공간 상관계수만으로 국소 차이를 판단하지 않고 절대차 지도와 꼬리 농도를 함께 확인했다.

꼬리 농도에는 따로 설명할 사례가 있다. 정상상태 POINT의 두 번째 seed 쌍에서 P95의 CPU/GPU 평균 절대차는 0.0014863014, CPU interseed 절대차는 0.0016935349로 그 비는 0.8776326이다. seed 300000 하나의 절대차 0.0029361725는 해당 CPU interseed 차이보다 약 1.734배 크다. 이 차이는 CPU P95 34.2854454의 약 0.00856%에 해당한다. 비교 기준인 두 CPU P95 자체가 매우 가까워 전체 농도장의 R보다 꼬리 지표의 비가 커졌다. 정상상태 합계 P99의 첫 번째 쌍에서도 비가 0.3163202였다. 사전 정의한 쌍 평균과 다른 진단을 함께 검토해 관측 시험의 수치 판정을 유지했다. 새로운 허용치를 추가하지 않았으며, 모든 개별 꼬리 차이가 CPU seed 변동보다 작다고 일반화할 수 없다.

고정 seed 0의 24/48상황 반복에서는 각 모드·배출원군·합계·분석 구간의 CPU 내부 세 쌍과 GPU 내부 세 쌍 모두 해독 배열이 정확히 같았다. CPU와 GPU 사이 배열은 정확히 같지 않았다. 이 반복성 비교는 이번 프로토콜에 미리 포함한 기술통계이며 추가적인 독립 seed를 제공하지 않는다. 서로 다른 여섯 seed 상태도 난수 스트림의 통계적 독립성을 입증하지 못한다. 세 쌍만으로 모집단 추론을 확정할 수 없어 `inference_inconclusive`를 유지한다. 격자·상황·배출원군·고정 seed 반복을 독립 표본으로 늘려 세지 않았다.

| 모드·상황 수 | CPU 중앙값 (s) | GPU 중앙값 (s) | 쌍별 속도비 중앙값 | 쌍별 속도비 범위 | CPU CV |
|---|---:|---:|---:|---:|---:|
| 비정상상태 24 | 41.733 | 8.092 | 5.131 | 5.033..5.260 | 1.96% |
| 비정상상태 48 | 89.640 | 13.961 | 6.523 | 5.745..6.780 | 7.39% |
| 정상상태 24 | 38.804 | 7.235 | 5.413 | 5.259..5.640 | 3.32% |
| 정상상태 48 | 105.685 | 12.645 | 8.358 | 6.135..15.257 | 51.22% |

시간 표는 프로세스 시작부터 종료까지의 세 반복을 요약한다. CV는 표본 표준편차를 평균으로 나눈 값이며, 속도비는 각 CPU/GPU 쌍에서 계산했다. 정상상태 48상황의 CPU 시간은 실행 순서대로 202.793, 105.685, 77.203초였다. GPU 시간 범위는 12.584..13.292초, CV는 3.06%다. 관측한 세 쌍에서는 GPU가 더 빨랐으나 8.358배를 안정적인 성능 배수로 제시할 근거는 부족하다. 전체 범위와 큰 CPU CV를 함께 제시해야 한다.

기존 로그를 보면 첫 CPU 실행의 상황 1..10과 11..48 중앙값은 각각 4.0444, 4.0565초였다. 두 번째 실행은 4.3452, 1.5948초로 상황 11부터 짧아졌고, 세 번째는 1.6266, 1.5758초였다. stdout의 dispersion 시간도 같은 변화를 보여 시작 비용만의 차이로 설명하기 어렵다. 세 실행의 process-tree RSS 최댓값은 83.03, 80.59, 81.21 MiB, 가용 RAM 최솟값은 22.36, 20.89, 21.77 GiB였다. 시작 전 quiet gate의 CPU 평균 사용률은 6.04%, 9.64%, 3.26%로 모두 기준을 통과했다. 실행 중 CPU 누적 시간·사용률·주파수·온도·문맥 전환·GC/JIT/tiering 사건은 기록되지 않았다. 따라서 process CPU-time/wall 비율을 계산할 수 없고, 외부 부하·발열·동시 분석 작업을 변동 원인으로 특정할 수 없다.

첫 세 상황을 제외한 경계 시간, 상황 시간의 합, 전체 프로세스 시간을 구분했다. GPU의 `kernel_device_ms`는 CUDA event 누적값의 상황별 차이로 검산했다. `fresh_kernel_ms`, `residual_kernel_ms`, `kernel_total_ms`에는 호스트 호출·동기화·상태 읽기가 들어가며 호스트 왕복 시간에 포함된다. 이 시간을 독립된 단계처럼 더해서 총시간을 만들면 중복 계산이 된다. 혼합 배출원 실행의 시간으로 POINT나 PORTAL 각각의 가속률을 산정할 수도 없다.

메모리는 표본 시점의 process-tree RSS/private, dotnet/Python RSS, 장치 전체 사용량을 구분해 확인했다. 표본 최댓값이 순간 최대치를 놓칠 수 있고, 프로세스 RSS 합계는 공유 페이지를 중복 포함할 수 있다. 현재 WDDM 조회에서는 프로세스별 VRAM을 얻지 못하므로 장치 전체 메모리나 시작값과의 차이를 GPU 프로세스의 VRAM으로 표기하지 않는다. 버퍼 할당·재사용 카운터 역시 애플리케이션이 계수한 범위다.

실제 GPU 실행의 해석에는 양의 CUDA event 시간, 증가하는 launch 횟수, 단일 배출원 기능시험, 고정 입력과 네 배출원군의 양의 출력, CPU 비교를 함께 사용한다. `phase_counts`는 완료된 GPU 요청을 호스트가 계수한 값으로, 커널 안에서 배출원별 입자를 직접 센 값은 아니다. 독립 결과 검토는 이 계측 범위를 유지하며, 개별 소스 유형의 장치 카운터를 측정했다고 주장하지 않는다.
